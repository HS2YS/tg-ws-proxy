# TG WS Proxy в Docker Compose

Этот вариант предназначен для постоянного запуска на VPS. Контейнер
автоматически перезапускается после сбоя и после перезагрузки сервера.

## Первоначальная настройка

На VPS должны быть установлены Docker Engine и плагин Docker Compose.
Замените `YOUR_FORK_URL` на HTTPS- или SSH-адрес вашего форка.

```bash
git clone YOUR_FORK_URL
cd tg-ws-proxy
cp .env.example .env
openssl rand -hex 16
nano .env
chmod 600 .env
```

Вставьте результат `openssl rand -hex 16` в `TG_WS_PROXY_SECRET` без префикса
`dd` или `ee`, а в `TG_WS_PROXY_PUBLIC_HOST` укажите публичный IPv4-адрес VPS
или DNS-имя без `http://` и `https://`.

После однократной настройки весь запуск выполняется одной командой:

```bash
docker compose up -d --build
```

Политика `restart: unless-stopped` поднимет контейнер снова после падения или
перезагрузки VPS. Если Docker не включён в автозагрузку вашей системы, включите
его отдельно.

## Получение ссылки

```bash
docker compose logs tg-ws-proxy 2>&1 | grep 'tg://proxy' | tail -1
```

Ссылка уже содержит публичный адрес, внешний порт и секрет из `.env`:

```text
tg://proxy?server=203.0.113.10&port=1443&secret=dd0123456789abcdef...
```

Логи содержат секрет. Не публикуйте их целиком и не добавляйте `.env` в Git.

## Основные настройки `.env`

| Переменная | Назначение | Значение по умолчанию |
|---|---|---|
| `TG_WS_PROXY_PUBLIC_HOST` | Публичный IPv4-адрес или DNS-имя VPS; обязателен | — |
| `TG_WS_PROXY_PUBLIC_PORT` | TCP-порт на VPS и в ссылке подключения | `1443` |
| `TG_WS_PROXY_SECRET` | Постоянный ключ: ровно 32 hex-символа; обязателен | — |
| `TG_WS_PROXY_BIND_IP` | Интерфейс VPS, на котором публикуется порт | `0.0.0.0` |
| `TG_WS_PROXY_DC_IPS` | Пары `номер_DC:IP` через пробел | `2:149.154.167.220 4:149.154.167.220` |
| `TG_WS_PROXY_CF_WORKER` | Один или несколько доменов Cloudflare Worker | пусто |

Внутри контейнера прокси всегда слушает `0.0.0.0:1443`. Поэтому, например,
`TG_WS_PROXY_PUBLIC_PORT=443` публикует порт `443` на VPS, не запуская процесс
в контейнере от root.

Дополнительные настройки (`Fake TLS`, пользовательские CF-домены, размер пула,
отладочные логи и другие) описаны комментариями в `.env.example`.

После изменения `.env` пересоздайте контейнер этой же командой:

```bash
docker compose up -d --build
```

Команда `docker compose restart` не подхватывает изменённые переменные.

## Проверка и обслуживание

```bash
# Состояние и healthcheck
docker compose ps

# Логи в реальном времени
docker compose logs -f tg-ws-proxy

# Остановка
docker compose down
```

Docker ограничивает локальные логи тремя файлами по 10 МБ. Healthcheck
проверяет наличие локального TCP-listener без тестового подключения к прокси;
статус `unhealthy` сам по себе не вызывает перезапуск, но встроенный watchdog
восстанавливает listener, а Docker перезапускает завершившийся процесс.

Не забудьте разрешить входящие TCP-подключения к
`TG_WS_PROXY_PUBLIC_PORT` в firewall VPS и в firewall/security group
провайдера.

## Настройка Telegram

Откройте полученную `tg://proxy` ссылку или добавьте прокси вручную:

1. Telegram → **Настройки** → **Продвинутые настройки** → **Тип подключения** → **Прокси**.
2. Выберите тип **MTProto**.
3. Укажите `TG_WS_PROXY_PUBLIC_HOST`, `TG_WS_PROXY_PUBLIC_PORT` и полный
   секрет из сгенерированной ссылки (с префиксом `dd`, либо `ee` для Fake TLS).
